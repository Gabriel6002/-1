# 机器辅助标注完整流程

> 目标：用 COCO 预训练 YOLO 自动预标注 + 人工快速修正，
> 比纯手工画框快 5~10 倍。适用于 mouse / keyboard / cup 这类 COCO 已有的桌面物体。

以下命令默认在该目录下的 `tools/` 里执行。

---

## 一、需要拍多少张（先看这个再动手）

| 项目 | 数量 | 说明 |
|---|---|---|
| **每类** | **200~250 张** | mouse / keyboard / cup 各 250 |
| **总计** | **约 750 张** | 3 类 |
| 其中：多物体同框 | ≥30%（约 220 张） | 一张图里放 2~3 个不同物体，标注时标全 |
| 纯背景负样本 | 30~50 张 | 桌面空的，不含任何目标 |

**为什么是 250 而不是更多**：这三类都在 COCO 里，`yolov8n` 预训练权重
已经"见过"，微调收敛极快，250 张就能到很高精度。选 COCO 没有的冷门物体才需要 500+。

**"一个物体"到底指什么**（容易搞混）：
- 拍摄张数是按**类别**算的：mouse 这一类总共 250 张，不是每个鼠标 250 张。
- 如果你有 3 个不同的鼠标，就把这 250 张分摊到 3 个鼠标上，各拍 ~80 张。
- **同一个鼠标原地不动连拍 250 张 = 只有 1 张有效数据**。多样性比数量重要得多。

**关于验收要测的"20 个物体"**：那是测试环节，用 20 个不同实物
（或同一物体的不同摆放）去测正确率，和上面的训练采集量是两回事。

---

## 二、采集：拍照时必须覆盖的变化

每个维度都要拍到，否则验收现场换个条件就掉链子：

| 维度 | 要覆盖 |
|---|---|
| 距离 | 近（物体占画面 1/2）、中、远（占 1/10） |
| 角度 | 俯视、45° 斜视、水平视角 |
| 旋转 | 物体自身转 0° / 90° / 180° / 270° |
| 光照 | 自然光、室内灯、台灯、半遮挡阴影 |
| 背景 | 白桌、木纹桌、有杂物、铺纸 |
| 遮挡 | 物体被挡住 20%~50% |
| 位置 | 画面中心、四角、边缘只露一半 |

⚠️ **最关键一条**：至少 1/3 的照片用**验收那台 Jetson 的 USB 摄像头**采集。
不同相机的色彩、噪声差异大，只用手机拍的数据，Jetson 上跑会掉点。

### 采集命令

**方式 A：用 Jetson 的 USB 摄像头**（推荐，和验收同一个相机）

在 Jetson 的 SSH 终端里，一次采一类：
```bash
cd ~/robotic_group/tools
python3 capture_images.py --class mouse --auto --interval 0.4 --limit 250
```
把 `mouse` 换成 `keyboard`、`cup` 各跑一次。
连拍时**手要一直慢慢移动物体和相机**，别原地不动。
按键：空格=单拍，a=自动连拍开关，u=撤销上一张，q=退出。
（Jetson 没接显示器时看不到预览窗口，用 `--auto` 盲拍即可，拍完复核时再看。）

**方式 B：用手机 / 相机拍**

随便拍，然后把照片拷进 `dataset/raw/<类别名>/` 下，
比如 `dataset/raw/mouse/`、`dataset/raw/cup/`。
手机照片有 EXIF 方向问题，先跑一遍预处理（见附录），避免标注和图对不上。

采集完，目录应该长这样：
```
dataset/raw/
├── mouse/     ~250 张
├── keyboard/  ~250 张
└── cup/       ~250 张
```

## 三、自动预标注（机器画框）

在 Mac 上跑（有 GPU 更快，这一步不实时，慢点也没事）：

```bash
python tools/auto_label.py \
    --images raw \
    --out labeled \
    --classes mouse keyboard cup \
    --model yolov8x.pt --conf 0.25
```

- `--classes` 的顺序 = 最终类别编号（mouse=0, keyboard=1, cup=2），**一次定死别改**。
- `yolov8x.pt` 是最准的预训练模型，首次运行自动下载约 130MB。
- 跑完产出：
  ```
  dataset/labeled/
  ├── images/       所有图片（统一改名，保证和标注同名配对）
  ├── labels/       自动生成的 YOLO 标注 txt
  ├── classes.txt   类别表
  ├── _preview/     画好框的预览图 ← 先翻这个看质量
  └── _review.csv   按可疑程度排序，优先复核这些
  ```

## 四、人工复核修正（关键，别跳过）

自动标注是"预标注"不是"全自动"，一定会有漏检、框歪、类别错。
验收看的就是数据质量，这一步决定成败。

### 4.1 先扫一遍质量
打开 `dataset/labeled/_preview/`，快速翻一遍所有预览图，
心里有数大概哪些标得好、哪些要改。

### 4.2 按可疑程度优先改
打开 `dataset/labeled/_review.csv`，它已经按
"框数少 + 置信度低"排好序：
- `n_boxes = 0` 的：模型完全没检测到，**必须手动补框**
- `min_conf` 很低的：框可能不准，重点看
- 正常的排在后面，扫一眼即可

### 4.3 用 labelImg 逐张修正

安装（只需一次）：
```bash
pip install labelImg
```

打开：
```bash
labelImg labeled/images
```

labelImg 里必做的设置：
1. 左侧格式按钮点成 **YOLO**（默认是 PascalVOC，切错存出来是 xml 不能训练）
2. `Open Dir` → 选 `dataset/labeled/images/`
3. `Change Save Dir` → 选 `dataset/labeled/labels/`
4. 菜单 `View → Auto Save mode` 打勾

常用快捷键：
- `d` 下一张，`a` 上一张
- `w` 画新框（补漏检的物体）
- 点中一个框按 `Delete` 删掉错框
- 双击框的标签可改类别

### 修正准则（全组统一，不然多人标注打架）
- 框**紧贴物体边缘**，别留白边，也别切掉物体
- 物体被挡 → 只框看得见的部分，别脑补
- 露出不到 20% 的 → 不标
- 画面里**所有**目标都要标（包括角落里的、另一个同类物体）
- 类别顺序永远是 mouse=0 / keyboard=1 / cup=2

## 五、划分数据集 + 质检

复核完，划分成 train/val/test 并生成 data.yaml：

```bash
python tools/split_dataset.py \
    --input labeled \
    --output dataset \
    --classes mouse keyboard cup --ratio 0.7 0.2 0.1

# 质检：--show 会抽样画框，人眼过一遍确认没标错
python tools/check_labels.py \
    --data dataset/data.yaml --show 20
```

`check_labels.py` 会报坐标越界、类别越界、空标注、类别不均衡等问题。
`--show 20` 随机抽 20 张画出框，**一定人眼过一遍**——框歪了、类别标反了脚本查不出来。

## 六、之后

数据集就绪后进入训练，见工程里的 `docs/运行说明.md` 阶段 B。
训练命令（Mac 上）：
```bash
yolo detect train --data dataset/data.yaml \
    --model yolov8n.pt --epochs 100 --imgsz 640 --batch 16
```

## 附录：手机照片预处理（方式 B 才需要）

手机拍的 JPG 带 EXIF 方向标记，标注工具显示正常但训练时可能读成转了 90°，
导致标注和图对不上、训练白做。把照片拷进 `dataset/raw_phone/` 后跑：

```bash
python tools/fix_phone_photos.py --src raw_phone --dst raw
```

（这个脚本需要时告诉我，我补上——它会固化方向、统一缩放到 1280、转成 jpg。）

## 时间估算

| 环节 | 耗时 |
|---|---|
| 采集 750 张 | 2~3 小时 |
| 自动预标注 | 10~20 分钟（跑脚本，人不用管） |
| 人工复核 750 张 | 1~1.5 小时（比纯手工的 3+ 小时快很多） |
| 划分 + 质检 | 10 分钟 |
| **合计** | **半天** |

5 个人分工的话，采集和复核都能再对半砍。
